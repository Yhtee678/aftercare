# Database schema

M2B defines only `schools`, `school_classes`, and `students`. Import table
definitions from `@/db/schema` and the server-only database connection from `@/db`.

- IDs are UUIDs generated by PostgreSQL. Required fields are non-null; student
  parent details and notes are optional. Phone numbers are text to preserve
  leading zeroes and international prefixes.
- `record_status` permits `ACTIVE` and `INACTIVE`, defaulting to `ACTIVE`.
  Deactivate records using status. Foreign keys restrict deletion of referenced
  schools/classes; there are no cascading deletes or hard-delete workflows.
- Class identity is unique by school, academic year, grade, and class name.
  Class names use PostgreSQL's ordinary case-sensitive text comparison.
  No grade/year ranges or unique school/student names are assumed.
- The class identity constraint supplies an index beginning with `school_id`.
  `students_school_class_id_idx` supports class rosters and foreign-key lookups.
- Both timestamps are `timestamptz` and default to `now()`. Drizzle's `$onUpdate`
  refreshes `updated_at` for ORM updates when no value is supplied. This is not a
  database trigger: direct SQL writers must set `updated_at` explicitly.
- A student's class reference represents only their current class. Future daily
  records must preserve the class context at the time of the record, rather than
  derive history from this mutable reference. No enrollment/history system exists yet.

## Migration commands

- `npm run db:generate -- --name=<name>` generates local SQL and a schema snapshot.
- `npm run db:check` checks local migration consistency.
- `npm run db:migrate` applies migrations to `DATABASE_URL`; run only when deployment
  is explicitly intended, after reviewing the SQL and target environment.

The initial M2B migration is generated only and has not been applied to Supabase.
The existing config loads `.env.local` quietly; never commit or print credentials.
